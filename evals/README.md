# POC evaluation suite

A repeatable, deterministic evaluation of the agent against the dental
marketplace catalog, policies and guardrails. Run it after any change to the
model, RAG, prompt, tools or avatar provider - the same cases, graded the same
way, so a regression is visible immediately.

## Run

```bash
# dev server + seeded SAM bot must be up (see docs/avatar-poc/HANDOFF.md)
node scripts/run-evals.mjs                 # full set
node scripts/run-evals.mjs --only rag      # one category
node scripts/run-evals.mjs --limit 20      # first N (free-tier friendly)
```

A report lands in `evals/reports/<timestamp>.{md,json}` with a pass rate, the
KPI table, and every failure with the answer that produced it.

## What it grades, and how

- **Deterministically**, against `dental-poc/catalog.json` (the verified answer
  key). No LLM judge, so grading is free of the provider quota and identical
  every run. A price case passes only if the answer contains that SKU's real
  price; a hallucination case fails if the answer names a SKU the catalog does
  not have.
- Cases live in `dental-poc/cases.json`, generated by `build-cases.mjs` (RAG
  cases derived from the catalog; scenarios hand-written). Edit either and
  re-generate.
- Categories map to the KPI dashboard: grounded accuracy, no-hallucination,
  policy precedence, context retention, escalation, unsupported-handling, plus
  server-side latency.

## What it does NOT cover (needs a human or real traffic)

- **First-audio latency, barge-in stop time, mic-denied / STT / avatar-API
  failure** - these are browser + voice-stack behaviours. The harness measures
  chat latency (retrieval + model + tools), which is the dominant term but not
  the whole voice round trip. Exercise the rest in a real browser session.
- **Conversion lift (video vs text)** - the product experiment. The analytics
  events (`avatar.*`, `apply_click`-style) and the experiment bucketing are in
  place to measure it against real users; it cannot be simulated.
